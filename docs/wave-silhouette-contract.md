# Wave silhouette and reading projection contract

This is stacked on verified receipt PR #148 at a55d3f57d372149fea6090e29d58941cae05dbed. The two baseline assertions used a flat rectangle where the wave renderer deliberately has a crest/trough envelope. A 1.92 x 1.12 nominal wave has a 1.92 x 1.288 analytic front envelope: aspect ~1.49068. Portrait target aspect .78 therefore needs ~1.91113 vertical stretch, not >2; the rectangle still needs ~2.19780. The actual target ratio, viewport limits, minimum readable height, native glyph compensation, immutable canonical form and uniform fit are asserted instead of relaxing tolerances.

The production change centralizes the existing 7.5% amplitude, two cycles and 28 segment contour. The Three.js cap retains its existing samples; the CSS polygon uses those same samples, normalized to the analytic envelope instead of its previous independently sampled 24-segment contour. No camera target, canonical dimensions, collision policy, billing, or receipt processing is changed. The bevel rim and artwork are separate from the interaction cap. A new test reconstructs coordinates from the CSS polygon and checks each against actual extruded cap vertices. The existing native-object gate now runs both formerly failing tests and the scene contract.
