# Collective mission experience

Verified baseline: PR #166 passed all six hosted workflows and 344/344 tests,
including mounted desktop/mobile adaptive recovery against source and static routes.

The existing validated, bounded world/branch journal is the source of experience.
Profiles are derived rather than stored in a new database: exact recorded source
attribution, distinct contributed and owner-completed tasks, closed-incomplete
contributions, confirmed changed and unchanged receipts, pending/conflicting
evidence, and non-dispatch. No source is credited merely for owning a task.
Known space/entity identities distinguish object specialization; legacy unknown
space contributes to descriptive totals only. Repeated changes do not increase
the number of completed or distinct changed tasks. This is observational
evidence, not model training, semantic knowledge, a provider identity proof,
or a success/failure rate.

The owner face shows scope-local profiles and top object histories. The existing
task.progress tool exposes a derived summary of only the attached task and
explicitly shared completed direct prerequisite receipts. No unrelated journal
records, session identities, or additional tools are exposed. Derived profiles
survive reload through existing persisted task history; no new grant or action
is restored. There is no cross-device learning or external agent invocation.

Recommendations retain the existing eligibility, unresolved-evidence and local
workload gates. Continuity is preferred first; then distinct completed tasks
with confirmed changes at relevant known space/entity addresses, then distinct
changed tasks, memory availability and stable identity. Raw receipt counts are
descriptive only. This is intentionally not an accuracy score, and does not
measure general skill. Recommendation approval still uses the existing fresh
scope, session and task checks. Old history without exact space identity cannot
be treated as a related object match.
