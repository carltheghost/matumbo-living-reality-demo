# Multi-agent mission handoff

This extension uses the existing task journal, native controller and owner controls; no new memory store or world engine. The owner selects the saved task and recipient, reviews the current source and epoch, then explicitly transfers it. A successful transfer preserves the journal and prior receipt attribution. A rejected transfer leaves the recipient's existing attachment intact. Pending or conflicting receipts block transfer and reserve the affected object across other attached tasks in the same world/branch and space. Legacy entries without a space conservatively reserve the entity ID.

The transfer is an ownership update in the local journal, not an action authorization or a provider identity proof. It does not restore native permissions or move objects, and unattached native edits remain separately governed by existing grants. Prior attachment epochs fail closed for journal operations. Closed journals retain unresolved reservations. Maximum 16 handoffs per task; existing v1 records remain readable. Browser-local persistence does not synchronize devices.
