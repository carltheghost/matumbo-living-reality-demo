# v0.3 neural integration experiment contract

This is the smallest neural milestone on the corrected v0.3 protocol. It is
an offline, CPU-scale behavior-cloning experiment for note-plus-spectrum
physical action selection. It is not a claim of autonomous planning,
general-language tool use, consciousness, world modeling, or superiority over
the control.

## Inputs and fixed schedule

The model receives only copies of `CorrectedEpisode.policy_observation()`.
The observation encoder consumes the exact note payload, typed diagnostic
measurement, typed feedback, and resource fields that the protocol whitelist
exposes. It never receives raw `advance()` arrays, episode snapshots, seeds,
gate-resonance arrays, oracle outputs, evaluator internals, or hidden world
state. The exact note text and the full 4 × 4 response matrix are therefore
inputs to the center before its final action.

The first milestone uses a declared fixed schedule: one zero-drive world
advance, lookup of the `instruction` note, diagnostic on fixed port 0, then
one neural actuation proposal. The model's final proposal contains a gate
choice and an explicit drive-frequency argument selected from the declared
four-frequency set `(0.55, 0.75, 0.95, 1.15)`. The executor validates and
executes those arguments; it does not fill in, correct, or answer for the
network. General autonomous scheduling and arbitrary tools are future work.

## Learned system and coded boundary

The full model has exactly four independently parameterized recurrent
peripheral modules and one structurally different gated recurrent center. The
center owns a differentiable addressable memory of two slots × six values and
the gate/frequency action heads. Peripheral hidden states, center hidden state,
memory slots, and weights are learned representations. Exact documents,
links, event history, authoritative world/tool results, budgets, and
checkpoint metadata remain coded SIMFABRIC state; no weight is treated as a
document, source file, universal program, or substitute for exact history.

Training is behavior cloning with cross-entropy labels for the final gate and
frequency. Labels are generated by the deterministic v0.3 oracle only while
constructing train/validation supervision. They are not present in model
inputs and are never called during evaluation. Reverse-mode gradients cover
the five recurrent state transitions, center memory read/write, and action
heads; the protocol simulator, SQLite workspace, tool execution, and
authoritative success predicate are outside the gradient boundary.

The matched single-controller control has the same encoded observations,
two-slot × six-value differentiable memory, fixed tools/schedule, optimizer,
step count, and validation cadence. It replaces the four peripherals plus
center with one recurrent controller; parameter counts are reported rather
than silently treated as equal.

## Data split and budget

Each split uses disjoint complete world seeds. Every episode also has a
`note-goal-id` consisting of target frequency, phase, and note-format variant;
exact goal IDs are disjoint across train, validation, and test. All four
declared frequencies occur in each split, so the held-out question is
note-payload/world generalization rather than an impossible unseen class.

- Train: 8 worlds × 4 goal IDs = 32 episodes.
- Validation: 4 worlds × 4 goal IDs = 16 episodes.
- Test: 12 worlds × 4 goal IDs = 48 episodes.
- Full and control trials: model seeds 7 and 17; control seeds 41 and 43.
- Optimizer: deterministic Adam-style updates, 180 steps per trial, one
  sampled train episode per step, validation every 30 steps, gradient norm
  clipping at 3.0, learning rate 0.012.
- Checkpoint selection: lowest validation loss only. Test success is read only
  after the selected checkpoint is fixed.
- Runtime target: one CPU process, small NumPy/autograd tensors, no network,
  credentials, paid compute, deployment, or external tools.

## Success and interventions

Primary success is the authoritative `CorrectedEpisode.success()` result on
each held-out episode, with all protocol budgets respected. The report records
every model/optimizer seed, per-episode raw success, action, failure reason,
and work/physics/residual accounting. It does not require the full model to
beat the control.

The same held-out episodes run causal interventions: a copied policy note is
replaced with a wrong target note; a copied policy measurement is replaced by
a donor measurement; a copied neural memory is erased before final action; and
the executor's actuation is disabled. No intervention mutates
`episode.note_result`; evaluator goals remain authoritative and unchanged.

Required checks are finite gradients to all five brain modules and initial
memory, JSON checkpoint/reload and trajectory replay, exact SQLite note/link
store integrity, protocol unit tests, and the corrected undriven timestep
refinement test. Results are written under
`experiments/vevo-agents/reports/generated/v03-neural-proof-report.json` and
the runnable command is:

```sh
PYTHONPATH=src python -m vevo_agents.v03_neural_proof \
  --output reports/generated/v03-neural-proof-report.json
```
